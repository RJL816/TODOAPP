# Android 番茄钟计时与提醒

## 用户行为

- 开始专注或休息后，通知栏与锁屏显示系统计时通知；暂停显示冻结时间，恢复继续计时。
- 在“专注 → 计时设置”中可开启悬浮窗，默认关闭。悬浮窗显示当前阶段的剩余时间（正计时专注显示已用时间），可拖动、点击返回应用。
- 关闭悬浮窗不会关闭通知栏计时。结束、放弃后移除计时通知和悬浮窗。
- 倒计时结束由系统发送高优先级通知。点击结束提醒进入专注页；开启提示音时使用系统通知声音与振动，关闭时发送静默提醒。
- 正计时专注没有预定结束时刻，由用户主动完成；休息仍然使用倒计时。
- 不主动唤醒屏幕，不强制全屏弹窗。通知弹窗、锁屏展示、声音和振动仍服从系统通知渠道设置、勿扰模式与锁屏隐私设置。

## 权限与后台

通知和到点提醒设置提供通知权限、闹钟和提醒权限入口。没有精确提醒权限时，结束通知降级为系统允许的不精确提醒，锁屏后可能延迟；关闭通知权限时，通知栏计时和结束提醒无法正常展示。

悬浮窗单独申请“显示在其他应用上层”权限；没有该权限仍可使用通知栏计时。后台设置打开当前应用的系统设置，供用户根据手机品牌允许后台运行；不自动申请忽略电池优化。

原生计时采用用户主动启动的 specialUse 前台服务和系统通知计时器。不为通知栏计时每秒更新通知；仅开启悬浮窗时每秒刷新其文本。按目标时刻计算剩余时间，暂停/恢复更新目标时间。

结束提醒由 flutter_local_notifications 持久化排程，独立于 Flutter 秒级刷新。清理闹钟独立移除运行通知和悬浮窗；暂停、放弃取消排程，旧阶段清理广播核对目标时刻。自然结束不会取消已发出或即将发出的结束提醒，避免竞争导致漏提醒。增加通知接收器和重启恢复接收器。

强行停止应用、撤销精确提醒权限，以及部分厂商的后台限制，会影响系统排程。再次打开应用按持久化时间恢复并记录已结束的会话。暂停的正计时恢复冻结值，重复到点回调不会重复记录。

## 验证范围

v1.0.9 发布前完整 Flutter 测试 222 项通过；全项目静态检查没有错误（保留既有提示与警告）。状态测试覆盖倒计时、正计时、暂停恢复、跨启动、最后半秒和重复完成，另验证平板玻璃调节、全局边缘回弹与 AI Markdown 排版。

Android 16 模拟器验证：升级恢复已有正计时、通知显示冻结时间、桌面通知倒计时、一分钟锁屏到点通知、到点清理计时服务、可选小窗显示正确剩余时间及拖动、暂停小窗显示冻结时间、点击小窗返回计时页、恢复后继续递减并到点清理。截图见 build/pomodoro-qa（本地构建产物）。
