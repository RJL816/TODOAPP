### 1.2 数据模型（Isar 集合）

- `TodoItem`：标题、完成状态、创建日期/时间戳、完成时间、类型（oneTime/recurring）、分类（work/life/study/health）、备注、排序权重
- `DailyCompletion`：每日习惯的按日完成记录（todoId + 日期），习惯状态不存 TodoItem 上
- `Course` / `SemesterConfig` / `Exam`：课程（星期、节次、周次范围字符串、学期）、学期配置（开学周一 + 总周数）、考试
- `Memo` / `Tag`：备忘录（软删除 + 回收站 + 置顶）与标签（IsarLinks 多对多）

### 1.3 已发现的问题清单（含用户直接反馈的两项）

**P0 交互缺陷（用户直接反馈）**
1. **Windows 窗口不能调整大小**：`main.dart` 中 `windowManager.setAsFrameless()` 移除了原生窗口框架（含拖拽边缘的 resize 命中测试），窗口固定 500×650；且无 minimumSize、不记忆窗口大小/位置。
2. **备忘录手机端左右分栏固定**：`memo_page.dart` 侧栏宽度写死 220/280px，窄屏（约 360dp）下编辑区只剩约 140dp，基本不可用。

**P1 逻辑缺陷**
3. 习惯创建日期污染历史统计：`getTodosForDate` 查询所有每日习惯时不按 `createdDate` 过滤，新建习惯会出现在过去日期且记为"未完成"，进而打断连续打卡（streak）回溯。
4. 统计页历史日期的习惯复选框可点击，但 `toggleTodo` 对非今天的习惯静默返回，表现为"点了没反应"。
5. 待办没有编辑功能（不能改标题/日期/分类/类型/备注），只有新增、勾选、删除。
6. **课程查询不按学期过滤**：`getWeeklySchedule` 等全部 `courses.where().findAll()`，而导入只清除同学期名的课程 → 换学期导入新课后两个学期的课混排。
7. 节次上课时间硬编码两处（`course_service._getCurrentPeriod`、`schedule_page.timeSlots`），显示与（未来）提醒各用一份，会漂移。
8. 课表没有手动编辑课程 UI；导入无预览、解析后直接覆盖整学期数据。
9. 备忘录回收站"30 天自动清理"（`cleanupOldDeletedMemos`）从未被调用，实为死逻辑。
10. 课程导入按固定表格结构解析（第 2 行学期、第 4–8 行节次），仅适配一种教务系统格式（已知限制，导入预览可缓解误导入）。

**P2 工程质量**
11. `assets/sounds/` 只有 .gitkeep，音效播放永远静默失败；根目录遗留拼写错误的 `assetssounds.gitkeep`。
12. README 下载说明中文件名首字母被制表符吞掉（`<tab>odo_app_v5.zip`）。
13. 死代码：`schedule_page._showXlsFormatDialog`、`memo_page._initService` 冗余初始化；`widget_service` 用 `print`。
14. 冒烟测试必然失败（未初始化 Isar 直接 pump 主页）。
15. 91 条 analyze info（`withOpacity` 弃用等）。
16. `SemesterConfig` 只取第一条，多学期并存时无法切换；`Exam`/`Course` 构造函数里学期名硬编码 `2025-2026-1`。

## 二、分阶段计划

### 阶段 1A：数据安全垫底 + P0 界面修复（第一批交付）

**1A.1 文档与测试基线**
- 功能清单、数据模型清单、构建命令、问题清单沉淀为 `docs/`（本文档即起点）。
- 修复冒烟测试；搭建服务层测试基建（Dart VM 下加载 Isar 原生库，跑真实数据库的单元测试）。

**1A.2 备份与覆盖恢复（明确备份时机）**
- 关键事实：**Isar 在 `Isar.open()` 时自动迁移 schema**；"变更前备份"必须发生在打开之前，打开之后再备份拿到的已是迁移后的库。
- 启动流程固化为：读应用数据版本号（存 SharedPreferences，独立于 Isar）→ 若为旧版本且存在旧库文件，**先复制原 .isar 文件**为带时间戳的备份，计算 SHA-256，并用临时目录中的隔离 Isar 实例试开验证可读（"可校验"的定义）→ 打开数据库（Isar 自动 schema 迁移）→ 执行应用层数据迁移（新字段默认值/回填）→ 迁移后跑一次全量导出，验证关键集合可读且条数与迁移前一致 → 写入新版本号。任一步失败：保留备份、明确提示用户，不静默继续。
- 全量 JSON 导出：7 个集合 + 学期/节次配置 + SharedPreferences 关键键值，带版本号与时间戳。
- 恢复本轮只做**覆盖恢复**（整库替换后重启验证）。
- **合并恢复本轮不做**：两台设备的 Isar 自增 ID 可能重叠，直接合并需重映射 `DailyCompletion.todoId`、备忘录-标签 IsarLinks 等关系数据，并需先设计稳定业务标识（如 UUID）与冲突规则——列为独立设计项（见第三节"跨设备与合并恢复"）。

**1A.3 Windows 窗口体验修复（P0-1）**
- 移除 `setAsFrameless()`，保留 `TitleBarStyle.hidden`（保留原生可调边框、只隐藏系统标题栏）。
- 设置 `minimumSize`（约 420×560）；默认尺寸放大到适合桌面（约 960×720）。
- 记忆窗口状态：关闭时保存大小/位置/是否最大化（SharedPreferences），启动时恢复并夹取到可见屏幕范围内。
- 标题栏支持双击最大化/还原；保留现有自绘标题栏（拖拽、最小化、关闭）。

**1A.4 备忘录手机端布局修复（P0-2）**
- 窄屏（宽 < 600dp）：改为单栏 master-detail——列表页 ↔ 编辑页切换，带返回；搜索、标签筛选留在列表页。
- 宽屏：保留左右分栏，侧栏宽度可拖拽调整（带最小/最大约束），记住宽度。

**1A.5 习惯统计修复 + streak 口径（定死并测试）**
- 修复 `getTodosForDate`/`getCurrentStreak`：习惯按 `createdDate ≤ 查询日期` 过滤，创建前的日期不出现、不算未完成。
- **streak 口径**：
  - 有效任务日 =（按创建日期过滤后）当天任务数 > 0；有效任务日全部完成计 1 天，存在未完成即中断；
  - 无任务日不计入、不中断；
  - 今天未全部完成不算中断（streak 以昨天为终点回溯），今天全部完成则从今天计入；
  - 回溯下界 = min(最早数据日期, 今天 − 366 天)，到达即停，避免无限回溯查询。
- 统计页历史日期的习惯复选框禁用（与首页行为一致）。
- 以上口径全部写成单元测试（含"习惯创建前日期不污染""无任务日不断 streak""回溯到下界即停"）。

**阶段 1A 完成标准**：analyze 0 错误、测试全绿（含习惯过滤与 streak 口径用例）、双平台构建通过；旧库升级路径具备"备份 → 迁移 → 导出验证"的自动化测试；窗口可自由调整并记忆大小；备忘录在手机上单栏可用。

### 阶段 2：双端提醒（工作量最大，含平台决策）

**决策（已定）**：Windows 采用**托盘驻留**方案——关闭按钮 = 退到托盘，进程常驻，可发系统通知；设置页与文档明示"托盘退出后提醒不可用"。任务计划程序方案作为后续可选增强（便携版挪动路径会失效，暂不做）。

**2.0 前置：依赖兼容性锁定**
- 所有新增依赖（flutter_local_notifications、tray_manager、local_notifier 等）必须先经 `flutter pub get` 解析 + 双平台构建验证，再随 `pubspec.lock` 锁定，不追最新版。
- 已核实：当前 SDK 为 Dart 3.12（master/dev），tray_manager 0.7.0 要求 Dart ≥3.13 不可用，锁定 0.5.3（要求 Dart ≥3.0）等兼容版本；若确需新版，"升级 SDK/切换 stable 渠道"单独立项评估，不在本阶段顺手做。

**2.1 数据模型**
- `TodoItem` 新增：`startTime`、`deadline`、`remindBeforeMinutes`（5/15/30/自定义）、`isReminderEnabled`（加字段走 1A.2 的备份+测试流程）。

**2.2 通知基建**
- Android：`flutter_local_notifications`——Android 13+ 通知运行时权限申请；Android 12+ 精确提醒引导用户授予"闹钟和提醒"特殊权限，未授予则降级为不精确提醒（UI 如实标注误差）；boot receiver 开机重排；提醒 id 由实体 id 派生，更新 = 先取消再排，防重复。
- Windows：`local_notifier` 系统通知 + `tray_manager`（0.5.3）托盘（托盘菜单：显示/退出）；验证运行中、最小化、托盘驻留三态提醒。
- 点击提醒打开对应内容：payload 带 type+id，冷启动与热切换两条路径都要处理。

**2.3 待办提醒**
- 新增/修改/完成/删除待办时正确排定或取消提醒。

**2.4 课程提醒：长排程窗口 + 可靠补排（修正"只排 7 天"的缺陷）**
- **排程窗口 = 本学期剩余全部周次**（数量有界：每周课程槽 × 剩余周数，通常数百条以内；若超出系统闹钟/插件排定数量上限，按"最近优先"截断，剩余部分由补排机制续上）。
- **补排触发（多重保险）**：打开 App 时全量重排；开机 boot receiver 重排；系统时区/时间变化监听重排；Android 可选 `workmanager` 周期任务（12 小时级）兜底重排——注意国产 ROM 省电策略可能延迟执行，列入真机验证清单。
- Windows：托盘驻留进程内直接定时触发，另加每 6 小时全量重排兜底。
- **验收用例（新增）**：① 连续 8 天以上不打开 App，期间课程提醒仍按点触发；② 设备重启后未来提醒完整恢复；③ 修改/删除课程或重新导入课表后，旧提醒被正确取消；④ 恰好跨周次边界（单双周）的课程提醒正确。

**2.5 扩展**：考试提醒；（阶段 4 后）训练计划提醒。

**2.6 测试与验证边界**
- 提醒时刻计算、周次换算、跨天重置、id 派生规则、排程窗口截断策略全部纯函数化并测试。
- Android 真机行为（权限、精确闹钟、重启恢复、杀后台、长时间不开 App、ROM 省电）无法自动验证，交付附真机测试清单，逐项标注"已验证/未验证"。

**阶段 2 完成标准**：双平台提醒可按时触发、可点击跳转、增删改后正确更新；Android 长时间不开 App 场景通过 2.4 验收用例；Windows 三态行为符合决策描述且有明确 UI 提示。

### 阶段 5：消费记录

- 模型：`Expense`（日期、金额**以整数"分"存储避免浮点误差**、分类、支付方式、备注、来源 manual/wechat、微信交易单号唯一索引用于去重）。
- 功能：快速记一笔、编辑删除、按月与按分类的支出汇总视图。
- **微信账单导入**：
  - 双入口：直接选 zip（主路径——archive ≥3.3.7 已支持 ZIP AES-256 解密，当前依赖 ^3.6.1 满足；密码由用户提供）；或直接选解压后的 CSV。
  - **兜底保留**：以真实微信导出样本实测解密与解析；解不开或格式变化时，引导用户手动解压后导入 CSV，不硬报错。
  - 解析官方导出 CSV 字段（交易时间/类型/对方/商品/收支/金额/状态/交易单号/商户单号/备注）。
  - 导入前预览全部交易 + 逐笔确认分类；按交易单号去重，重复跳过并列出。
  - **自动同步不做**：微信支付没有面向个人账单的官方开放 API（商户接口不适用），不通过模拟登录、抓包、读取私有数据等方式实现；此结论写入用户文档。
- **账本口径（定死并测试）**：
  - **消费（支出）**：计入消费统计。
  - **退款**：优先按交易单号/商户单号关联原消费并标记为该笔冲减；关联不上则单列为退款条目。月度与分类统计默认展示**净支出**（支出 − 退款），可切换查看毛支出与退款合计。不允许仅凭状态字段含"退款"就静默忽略。
  - **中性（收/支 = "/"）**：零钱充值/提现等，默认不导入，预览中分组列出，可手动勾选导入（不计入消费统计）。
  - **转账**：转给他人的转账虽在 CSV 中记为"支出"，默认标记为"转账"类型、不计入消费统计（避免虚增消费），预览中单独分组，用户可勾选计入。
  - **收入类**（红包、退款到账等）：默认不导入，可勾选。

## 三、贯穿各阶段的要求

1. **数据安全（备份时机已修正）**：**首次用新版本打开旧数据库之前**完成可校验的原库备份（在 `Isar.open()` 之前复制 .isar 文件 + 哈希 + 隔离实例试开验证）——因为 Isar 在打开时会自动迁移 schema，打开后无法再拿到迁移前数据；迁移后以全量导出验证。后续所有阶段的 schema 变更沿用同一机制并配套迁移测试。
2. **同步口径（如实声明）**：本地 Isar 数据**不会自动跨设备同步**，两台设备各自独立。文件级导出/覆盖恢复可作"手动搬家"。**跨设备合并恢复与云同步列为独立设计项**：合并需先引入稳定业务标识（UUID）并设计 `DailyCompletion.todoId`、备忘录-标签关系的 ID 重映射与冲突规则（如记录级 last-write-wins），本轮不做、不暗示。
3. **统计口径**：待办完成率、专注时长、训练次数、消费金额（净支出）四类指标分别展示，不合成单一完成率；streak 口径见 1A.5，账本口径见阶段 5。
4. **测试**：提醒时间计算、排程窗口与截断、课表周次、跨天重复任务、streak 口径、账单去重与分类、数据迁移均有单测；每阶段跑 `flutter analyze`、`flutter test`、`flutter build windows --release`、`flutter build apk --release`。
5. **验证边界**：Android 真机后台/权限/重启/长时间不开 App 行为与 Windows 关闭态提醒等无法自动验证的项，逐条在交付说明中标注实际验证状态，不用页内计时器冒充后台提醒。
6. **依赖策略**：新增依赖一律"解析 + 双平台构建验证后锁定版本"（见 2.0）；Isar 3.1 本轮不升级（已停止活跃维护属长期风险，未来单独立项迁移），避免本轮升级面失控。
